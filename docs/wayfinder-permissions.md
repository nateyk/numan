# Wayfinder generated directories need correct ownership

`resources/js/routes` and `resources/js/actions` are generated by Wayfinder and are
listed in `.gitignore`. They were created by an earlier `root` process inside the
container, which left some subdirectories owned by `root` while the project runs as
`nate`.

Consequences:

- `php artisan wayfinder:generate` aborts with
  `file_put_contents(...): Failed to open stream: Permission denied`
  the first time it reaches a root-owned file.
- `rm -rf` on those directories also fails, because deleting a file needs write
  permission on the directory that contains it.

## Fix

Run from the project root (adjust the username if yours differs):

```bash
sudo chown -R "$(id -un):$(id -gn)" resources/js/routes resources/js/actions
```

Inside the DDEV container the same thing can be done without leaving your shell:

```bash
ddev exec -s web -u root bash -c \
  'chown -R "$(id -un):$(id -gn)" /var/www/html/resources/js/routes /var/www/html/resources/js/actions'
```

Then verify:

```bash
ddev exec php artisan wayfinder:generate
```

## Why route names matter here

Wayfinder turns a route name into a JavaScript export. A route named `2fa-required`
produces the invalid identifier `2faRequired`, which breaks `npm run build`:

```
resources/js/routes/admin/index.ts(438,6): error TS1351:
  An identifier or keyword cannot immediately follow a numeric literal.
```

This was previously worked around by hand-editing the generated files, which the
next regeneration silently undid. The real fix is to name routes so the generated
identifier is valid. Both offenders are now renamed:

- `admin.2fa-required` -> `admin.two-factor-required`
- `workspace.2fa-required` -> `workspace.two-factor-required`

URLs and Inertia component names are unchanged; only the route names moved.
`app/Http/Middleware/RequireTwoFactor.php` and the affected tests were updated to
match.
